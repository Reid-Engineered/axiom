Axiom — UI Design Handoff

A complete description of the Axiom desktop learning environment as designed — system, navigation, all twelve screens, and the invariants that must survive implementation. Written to be handed to another AI or engineer as the source of truth.

Target runtime: Tauri, multi-platform (macOS, Windows, Linux). Native-desktop feel, no platform-specific chrome — a 38px draggable strip at the top of the window, each OS supplying its own decorations. The written spec also exists as AXIOM-HANDOFF.md; full-resolution frames are in screenshots/.

Product model
Goal ──guides──> Workspace ──contains──> Concepts ──related to──> Concepts
                     │                        │
                     ├──enables──> Modules (tools)
                     └──records──> Sessions, notes, practice history, mastery
Workspace — curated learning environment for one subject. Owns goals, concepts, material, history, enabled modules, preferences. Chosen over “Collection”.
Goal — living object: verbatim natural-language text plus inferred structure (deadline, mastery type, pacing, scope). One primary active goal; history retained.
Concept — semantic node with prerequisite / related / leads-to edges, a mastery state, and links to notes, practice, visualizations, tutor threads.
Module — a capability enabled inside a workspace. Never a navigation destination; never described in developer language.
Session intent — short-term goal (“practice 30 minutes”), distinct from the workspace goal.
Mastery — five named states: New · Developing · Familiar · Strong · Mastered. The word is the indicator; the ring is shorthand. States decay honestly (“was Strong”). Never a percentage, never a chart.
Offline — a workspace-level promise. Resources and modules are Works offline · Online enhanced · Internet required.
Goal states — Guiding · Waiting · Met · Resting. Exactly one goal guides, and it alone shapes recommendations.
Design system

Warm neutral surfaces, exactly two accents sharing lightness and chroma, system UI type for interface and STIX Two Text for mathematics. Sidebar 232px · drag strip 38px · workspace toolbar 38px · session toolbar 44px · radii 7–16 · 1px hairlines. Note for implementers: font: 400 12px/1 inherit is invalid CSS and is silently dropped — use longhands and let family inherit.

Content #FBFAF8 · chrome #F2F1ED · recessed #E9E7E2 · ink #1C1B19 · action oklch(.50 .13 258) · mastery oklch(.50 .13 150). Amber oklch(.65 .12 60) only for a named mistake; no red anywhere.

Navigation — chosen structure A

Home, Marketplace, then workspaces. Only the open workspace expands, into Overview / Concepts / Material / Tools; the tree never exceeds two levels; modules are never rows here. The sidebar is absent on first launch and hidden only in Full Visualization mode, which offers a single “‹ Session” return.

Rejected but recorded: B icon rail + header switcher (max content width, weaker recognisability); C sidebar scoped to one workspace (deepest focus, harder cross-subject work).

The twelve screens

1 · First Launch

Centred 520px column. One question, one field pre-filled with a ghost example, one button. Below a hairline, three text rows in ascending commitment: install a template / import a syllabus / explore a sample. No sidebar, no account step, no tour, no mention of modules.

2 · Create Workspace

Two fields: subject, and “what are you trying to accomplish?” in plain language. The “Axiom read that as” panel shows inferred structure as removable chips with an Adjust link that expands level, materials, and pacing in place. Deadline and starting level are never asked as form fields — they are inferred and correctable.

3 · Home

One line of remembered context, one Continue card that restates the actual half-finished problem typeset and holds the visualization's last camera position, then three workspace cards (name, goal, unlabelled 3px progress, last concept). Templates / Marketplace / Import are a quiet footer row. No dashboard, no analytics.

Alternate — session-intent led. “How much time do you have?” and a plan sized to fit, each row stating its reason. Strong for exam season; presumes one active workspace. Could ship as a preference.

Alternate — library led. No sidebar; workspaces are the page and Continue shrinks to a resume strip. Good for four or five subjects, wasteful for one.

4 · Workspace Overview

Answers “where am I, what next” in the first 300px: title, goal, Continue, and a Recommended block that states its own diagnosis. Concept rows use human status plus the mastery glyph. Right rail holds four tools, recent artefacts, and one panel proposing a goal change.

5 · Active Study Session

Stacked layout: visualization dominant on top, problem + working below-left, tutor below-right. The selected term in the integral is bound to the readout under the visualization and to “Ask about x”. The tutor is a panel asking one diagnostic question with three answers — not a chat log. The sidebar stays: a session is a mode of the workspace.

Rejected: problem-dominant with the visualization as a narrow inspector (good for solving, poor for intuition); immersive visualization with floating panels (striking, least stable).

6 · Full Visualization Mode

The only mode that hides navigation, with a single “‹ Session” return. Four verbs visible and everything else under More…; Bounds panel with two sliders and Advanced…; a selection inspector that reads out the primitives the scene was composed from and offers “Ask the tutor” carrying the object as context.

7 · Concept View

Mastery as a glyph plus one sentence — “You can apply this independently”. Two paragraphs, the second quoting the learner's own heuristic back with evidence. Verbs: Practice / Ask / Explain it back. Rail: Builds on and Leads to, diagnostic practice history, notes excerpt.

8 · Workspace Tools

On / Off, never install / uninstall. One reassurance at the top that turning something off destroys nothing. Each row says what the module does for learning and what context it sees. Trust badges are quiet. One suggestion at the bottom, justified by observed behaviour.

9 · Module Marketplace

Opens on “For your Calculus II workspace” — an extension of the learning environment, not a store. Templates sit beside modules as equal citizens. Trust reads as provenance; community modules look ordinary, never risky. A dashed “Load local module” row for tinkerers, present and unpromoted.

10 · Module Detail

Install is workspace-scoped (“Install to Calculus II”), and “Try it first” runs the preview live and sandboxed. Permissions are titled What it can see and written as sentences with defaults visible. “Works with” shows coordination between modules — the antidote to modules feeling like separate apps.

11 · Goal Editing

A sheet over the workspace, not a settings page, using the same natural-language field as Screen 2. The What changes panel previews consequences in learning terms and ends with the promise that nothing is deleted. “Goal history” keeps goals living objects rather than one-way switches.

12 · Command Palette

One query, four kinds of result: actions, concepts, your work, marketplace. Workspace-scoped, phrased as things to do, and the top hit carries a plain-language consequence so ⏎ is never a leap of faith. ⌘K is the only shortcut a beginner needs, and the sidebar advertises it.

Current system components

These supersede the earlier four-bar mastery glyph and the Explain / Practice / Reflect segmented control. Where an older screenshot disagrees, this sheet is authoritative: five named mastery states, a recommendation that can show its reasoning, three offline states, session intent instead of mode tabs, and a tutor context anchor.

Scale behaviour — pressure-tested

The same layouts under a semester of real content. These behaviours are part of the design, not later optimisations.

Returning after two weeks

Continue is replaced, same slot and weight, by three lines of recovery tied to mastery states — what held, what didn't, what changed underneath you — then a 5-minute refresher or straight back to the exact problem. Decay is stated honestly: “was Strong”. “While you were away” is three dated lines and then stops.

87 concepts

Never opens flat. Needs work first, ordered by what it blocks; everything else collapsed by chapter with a five-ring state profile. Filters are actionable counts, not taxonomy. Graph is a toggle; the rail shows one concept's prerequisite chain and everything attached to it.

A 712-page textbook

Reached through concepts and search — there is no folder view. Results are typed and each carries the reason it matters to this learner. Eighteen chapters compress into a four-segment bar; out-of-syllabus chapters stay available but never surface in recommendations.

Hour three, forty tutor exchanges

The panel never becomes a transcript: exchanges collapse into “What we've settled”, promotable to concept notes, with history behind “Earlier today”. Explanations can be pinned to the object. The sidebar auto-collapses to a rail during deep focus. One protective break suggestion, in the tutor's voice.

The learning canvas

The one sanctioned inversion of the palette: the chrome is restrained everywhere else so the mathematics can be expressive. The equation sits under the object, the dragged term tinted the same hue as the geometry it controls. Five controls visible; the rest on ⌥ or More…. “Back to problem” keeps it a detour, not a destination.

Offline, twenty modules, four goals

One offline sheet with honest sizes and a plain account of what degrades rather than breaks. Twenty modules group by where they appear, and none of them adds a sidebar row. Four goals, exactly one Guiding.

Invariants to preserve
  1. Simple by default, powerful by choice — one obvious next action per screen; advanced controls behind Adjust / Advanced… / More… / All tools.
  2. Never expose configuration merely because it exists, and never use developer vocabulary (package, manifest, dependency, runtime, API) in the learner interface.
  3. No dashboards, no percentages, no streaks, XP, badges, or leaderboards. Progress is named mastery states plus capability sentences.
  4. Feedback diagnoses, never merely marks. Amber for a named mistake; no red; no celebration.
  5. Modules are capabilities inside a workspace, never navigation destinations, and they share workspace context.
  6. Visualization is composed from verified primitives and shared across tutor, practice, explanation, notes, assessment.
  7. The tutor is a contextual panel that already knows what you are looking at — Axiom is not a chatbot.
  8. A learner returning after three days never reconstructs what they were doing; the Continue surfaces do it for them.
  9. Goals are living objects: changing one previews its consequences and destroys nothing.
  10. Two accents, two type families, one placeholder treatment. Any new surface must be expressible in that vocabulary — the dark learning canvas is the single exception, and only for the mathematical object itself.
  11. Permanent navigation never grows with capability: modules surface contextually, and the four workspace areas are the maximum.
  12. Offline is a promise, surfaced only where it changes a decision.
