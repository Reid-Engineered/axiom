# Synthesis Report: Volumes of Revolution (Cylindrical Shells)

## Source scope
- **Primary Text**: OpenStax *Calculus Volume 2* (Senior Contributing Authors: Gilbert Strang & Edwin "Jed" Herman; OpenStax / Rice University, 2016; Digital ISBN-13: 978-1-947172-14-2).
- **Chapter Analyzed**: Chapter 2 (*Applications of Integration*).
- **Core Section**: Section 2.3 (*Volumes of Revolution: Cylindrical Shells*, pp. 137–152).
- **Supporting Section**: Section 2.2 (*Determining Volumes by Slicing*, pp. 118–137) for comparative methodology and cross-sectional slicing references.

---

## Concepts selected

1. **`shell.method_vertical_axis` (The Method of Cylindrical Shells: Vertical Axis of Revolution)**
   - *Rationale*: This is the central conceptual foundation of Section 2.3 (Rule 2.6). It establishes the geometric decomposition of a 3D solid of revolution into nested cylindrical shells with representative radius $r(x)$ and height $h(x)$, integrated with respect to $x$. It covers standard rotation about the $y$-axis, regions bounded between two curves, and shifted rotation about vertical lines $x = k$.

2. **`shell.method_horizontal_axis` (The Method of Cylindrical Shells: Horizontal Axis of Revolution)**
   - *Rationale*: OpenStax Section 2.3 explicitly formulates the horizontal counterpart rule (p. 142) where rotation occurs about the $x$-axis and integration is performed with respect to $y$, $V = \int_c^d 2\pi y g(y)\,dy$. Isolating this into its own concept allows Axiom Practice and diagnostic tutors to identify variable-of-integration confusion.

3. **`method_selection.volume_of_revolution` (Method Selection for Solids of Revolution)**
   - *Rationale*: OpenStax Section 2.3 devotes a dedicated subsection (*"Which Method Should We Use?"*, pp. 145–147) and Example 2.17 to comparing the cylindrical shells method against the disk and washer methods from Section 2.2. Distinguishing when one method requires fewer integrals or simpler algebraic expressions is an essential higher-order calculus skill.

## Objectives

1. **`shell.setup_radius_height_y_axis`**
   - *Learner ability*: Identify and express the geometric shell radius $r(x)$ and shell height $h(x)$ for a region revolved around a vertical axis (either the $y$-axis or a shifted vertical line $x = k$).
   - *OpenStax basis*: Supported by Section 2.3 derivation (pp. 138–140), Rule 2.6, and Example 2.15 (pp. 142–144).

2. **`shell.compute_volume_y_axis_single_curve`**
   - *Learner ability*: Calculate the exact volume of a solid generated by revolving a region under a single continuous nonnegative function $y = f(x)$ over $[a, b]$ around the $y$-axis using $V = \int_a^b 2\pi x f(x)\,dx$.
   - *OpenStax basis*: Directly supported by Rule 2.6 (p. 140), Example 2.12 ($y = 1/x$), and Example 2.13 ($y = 2x - x^2$).

3. **`shell.compute_volume_y_axis_between_curves`**
   - *Learner ability*: Calculate the exact volume of revolution around the $y$-axis for a region enclosed between two curves $y = f(x)$ and $y = g(x)$ by setting up $h(x) = f(x) - g(x)$.
   - *OpenStax basis*: Directly supported by Example 2.16 (pp. 144–145, region between $y = \sqrt{x}$ and $y = 1/x$) and Checkpoint 2.16 ($y = x$ and $y = x^2$).

4. **`shell.compute_volume_shifted_vertical_axis`**
   - *Learner ability*: Formulate the shifted shell radius $r(x) = |x - k|$ and evaluate the volume of revolution for a region rotated around a non-coordinate vertical line $x = k$.
   - *OpenStax basis*: Directly supported by Example 2.15 (pp. 142–144, revolving $y = x$ around $x = -1$) and Exercises 144–148.

5. **`shell.compute_volume_x_axis`**
   - *Learner ability*: Set up and evaluate the cylindrical shell integral with respect to $y$, $V = \int_c^d 2\pi y g(y)\,dy$, for a region revolved around the $x$-axis.
   - *OpenStax basis*: Directly supported by the Rule for Solids Revolved around the $x$-axis (p. 142) and Example 2.14 ($x = 2\sqrt{y}$ over $[0, 4]$).

6. **`shell.select_optimal_method`**
   - *Learner ability*: Analyze a bounded planar region and choose between slicing (disks/washers) and cylindrical shells based on cross-section alignment and the required number of non-overlapping integrals.
   - *OpenStax basis*: Directly supported by Section 2.3 subsection "Which Method Should We Use?", Figure 2.34, and Example 2.17 (pp. 145–147).

## Problem families

Knowledge Package v1 has no schema for parametric problem generation — no `generator`,
`parameters`, `constraints`, `promptTemplate`, `canonicalSolution.expression`, `validator`,
templated hints, `difficulty`, or `status` field (spec §19). That machinery is dropped, not
carried forward in any form; it survives only as design evidence in this report's history
and in the brainstorm/spec documents. Six of the seven families below became freshly
authored, statically worded `Example`s — one concrete, independently-verified parameter
instantiation each, replacing the generator's sampled range. The educational purpose and
OpenStax basis below are unchanged from the original design rationale; parameterization/
constraint/verification-strategy notes are historical and describe how each instance was
chosen, not a live mechanism.

1. **`pf-shell-y-poly` → `shell.example_y_poly` (Polynomial Bounded Region around $y$-axis)**
   - *Educational purpose*: Practice setting up and integrating polynomial shells $V = \int_0^b 2\pi x (c x - x^2)\,dx$.
   - *OpenStax basis*: Example 2.13 ($y = 2x - x^2$) and Checkpoint 2.13 ($y = 3x - x^2$).
   - *Instance chosen*: $c = 4$, $b = 3$ (i.e. $f(x) = 4x - x^2$ over $[0, 3]$), staying within the family's original range ($c \in [2, 6]$, $b \le c$) but distinct from Example 2.13's own coefficients.
   - *Solution*: $V = 2\pi\left(36 - \frac{81}{4}\right) = \frac{63\pi}{2}$.
   - *Limitations*: Restricted to quadratic polynomials with root at origin.

2. **`pf-shell-y-reciprocal` → `shell.example_y_reciprocal` (Reciprocal Function Bounded Region)**
   - *Educational purpose*: Reinforce how cylindrical shells simplify functions of the form $k/x$ because $x \cdot (k/x) = k$, turning the integrand into a constant.
   - *OpenStax basis*: Example 2.12 ($y = 1/x$ on $[1, 3]$) and Exercise 128.
   - *Instance chosen*: $k = 3$, $a = 1$, $b = 4$ (i.e. $f(x) = 3/x$ over $[1, 4]$).
   - *Solution*: $V = 2\pi \cdot 3 \cdot (4 - 1) = 18\pi$.
   - *Limitations*: Only applies to simple hyperbola/reciprocal curves.

3. **`pf-shell-y-between-curves` → `shell.example_y_between_curves` (Region Between Two Intersecting Curves)**
   - *Educational purpose*: Practice computing the shell height as $h(x) = f(x) - g(x)$ and finding intersection bounds.
   - *OpenStax basis*: Example 2.16 and Checkpoint 2.16 ($y = x$ and $y = x^2$).
   - *Instance chosen*: $m = 2$ (i.e. $f(x) = 2x$, $g(x) = x^2$, intersecting at $x = 0, 2$).
   - *Solution*: $V = 2\pi\left(\frac{16}{3} - 4\right) = \frac{8\pi}{3}$.
   - *Limitations*: Uses standard polynomial intersections with exact roots.

4. **`pf-shell-shifted-vertical-axis` → `shell.example_shifted_vertical_axis` (Rotation Around Shifted Vertical Axis $x = -k$)**
   - *Educational purpose*: Evaluate learner mastery of adjusted shell radius $r(x) = x - (-k) = x + k$.
   - *OpenStax basis*: Example 2.15 (rotation of $y = x$ on $[1, 2]$ around $x = -1$) and Exercise 144.
   - *Instance chosen*: $k = 1$, $a = 1$, $b = 2$ (i.e. $f(x) = x$ over $[1, 2]$ around $x = -1$) — this is Example 2.15's own instance, cited `direct` rather than `derived`.
   - *Solution*: $V = 2\pi\left[\frac{x^3}{3} + \frac{x^2}{2}\right]_1^2 = \frac{23\pi}{3}$.
   - *Limitations*: Covers left-shifted vertical lines; right-shifted lines ($x = +K$ with $K \ge b$) remain unrepresented (see "Unresolved gaps").

5. **`pf-shell-x-axis-dy` → `shell.example_x_axis` (Shells Revolved Around $x$-axis)**
   - *Educational purpose*: Train the learner to integrate with respect to $y$ when revolving horizontal shells around the $x$-axis.
   - *OpenStax basis*: Rule p. 142, Example 2.14 ($x = 2\sqrt{y}$ on $[0, 4]$), and Exercises 134–137.
   - *Instance chosen*: $x = 2\sqrt{y}$ over $[0, 4]$ — Example 2.14's own instance, cited `direct`.
   - *Solution*: $V = 4\pi\left[\frac{2}{5}y^{5/2}\right]_0^4 = \frac{256\pi}{5}$.
   - *Limitations*: Uses power functions with fractional exponents.

6. **`pf-shell-setup-integrand` → `shell.example_setup_integrand` (Diagnostic Setup Formulation)**
   - *Educational purpose*: Isolate and diagnose the subskill of formulating the shell integrand $2\pi r(x) h(x)$ without the confounding arithmetic of antidifferentiation.
   - *OpenStax basis*: Conceptual derivation steps in Section 2.3 (p. 139, p. 143).
   - *Instance chosen*: $f(x) = x^3$ over $[0, 1]$ around $x = -2$ (i.e. $n = 3$, $k = 2$ in the family's original notation).
   - *Solution (unevaluated integrand, per the diagnostic's own scope)*: $2\pi(x + 2)x^3 = 2\pi\left(x^4 + 2x^3\right)$.
   - *Limitations*: Pure setup probe; does not test definite integration arithmetic.

`pf-method-select-integral-count` is not in this list — it did not migrate. See "Rejected
candidates" below.

## Structural inferences
1. **Explicit Separation of Horizontal and Vertical Shells**: While OpenStax groups both under Section 2.3, we separated `shell.method_vertical_axis` and `shell.method_horizontal_axis` into distinct concept nodes. This enables Practice to diagnose variable-of-integration confusion ($dx$ vs. $dy$).
2. **Atomic Diagnostic Objective for Setup**: OpenStax blends setup and evaluation into worked examples. We created `shell.setup_radius_height_y_axis` and `shell.example_setup_integrand` to isolate integrand assembly from antiderivative computation.
3. **Formalized Parameter Invariants (historical, pre-v1)**: The original problem-family design used concrete OpenStax numbers (e.g. $y = 2x - x^2$, $[0, 2]$) as sampling ranges, with dependent integer bounds expressed as `{ "parameter": "<id>", "offset": <integer> }`. Knowledge Package v1 has no parametric-generation schema (spec §19), so this described a mechanism that no longer exists; it is kept here as the rationale for why each migrated `Example`'s single instantiation sits where it does within the original range.
4. **Manifest Content Inventory (superseded)**: `package.json` used to explicitly list concept, objective, and problem-family IDs so consumers did not need to directory-scan the package. `package.toml` carries no such inventory — Knowledge Package v1's loader discovers entities by deterministic filesystem scan of `concepts/`, `objectives/`, and `examples/` (spec §12), so a duplicate manifest listing would just be another thing to keep in sync.
5. **Single-pass Template Substitution (historical, pre-v1)**: The dropped templating mechanism replaced exact `{key}` tokens once without evaluating arithmetic; nested LaTeX grouping such as `x^{{n}+1}` preserved the exponent expression after substituting `n`. v1 `Example`s are static Markdown with no templating.
6. **Provenance Collapse to a Single Source**: The pre-v1 `provenance.json`'s 11 flat entries collapsed into the package's one real `Source` (`src.openstax_calc2`) plus a per-entity `SourceLocator`-based citation on each `Concept`/`Objective`/`Example` (`provenance_refs[].locator`), per the brainstorm's headline reconciliation finding. Each entity's `direct` vs. `derived` `ProvenanceKind` now makes the earlier prose-only "structural inference" claims machine-queryable: `direct` means the entity transcribes an OpenStax example's own numbers, `derived` means it's a freshly authored instance within that example's method (see the "Problem families" table above for which is which).

## Unresolved gaps
1. **Right-shifted Vertical Axes**: OpenStax Section 2.3 mentions in text that vertical lines in the right half-plane can be used (where radius is $k - x$), but primarily details left-shifted axes ($x = -k$). Right-shifted vertical axes are omitted from `shell.example_shifted_vertical_axis` to avoid ambiguity until a verified instance is authored.
2. **Washer vs. Shell Direct Equality Benchmarks**: Example 2.17 mentions ease of evaluation, but does not provide a formal metric for algebraic complexity beyond the number of integrals.
3. **Example 2.17 Source Reconciliation**: For the stated triangle revolved about the y-axis, direct geometry gives one washer integral in $y$ and two shell integrals in $x$. The package's source text is unavailable, while the pre-v1 `provenance.json` recorded the opposite claim; this is why `pf-method-select-integral-count` was excluded from the v1 migration rather than converted into an `Example` — see "Rejected candidates" below.
4. **External Disk/Washer Prerequisite**: `method_selection.volume_of_revolution` depends on disk/washer knowledge as well as both shell-method concepts, but this package has no disk/washer concept to link. Knowledge Package v1's `prerequisite_ids` only resolves within the same package (spec §12) — it has no field for a cross-package dependency, so this gap is no longer representable in the package at all, not merely undeclared. Resolving it needs either a disk/washer package of its own or a future cross-package reference mechanism, neither of which exists yet.

## Rejected candidates
1. **Trigonometric Shells ($\int 2\pi x \sin(x^2)\,dx$)**:
   - *Reason for exclusion*: Requires substitution technique from Section 1.5/3.1 inside a Stage 8 geometry package. Excluded to keep the reference package focused on geometric shell formulation rather than advanced substitution.
2. **Bundt Cake / Torus Modeling Problems (Exercise 107)**:
   - *Reason for exclusion*: Highly specialized geometry requiring additional geometric modeling assumptions not generalized across the textbook section.
3. **Full Multi-variable Slicing Comparison Suite**:
   - *Reason for exclusion*: Exceeds the target size for this small reference package (kept to 3 concepts, 6 objectives, 6 examples).
4. **`pf-method-select-integral-count` (Method Selection Diagnostic)**:
   - *Reason for exclusion*: Excluded from the v1 migration entirely, not converted to an `Example`, per spec §19's corrected conclusion. Its geometry (a triangle bounded by $y = x$, $y = 2 - x$, $y = 0$, revolved about the $y$-axis) was independently re-derived during task `049` — one washer integral in $y$, two shell integrals in $x$ — but the unavailable OpenStax source text and the pre-v1 `provenance.json`'s citation claimed the opposite count, and that contradiction was never resolved against the actual source. It remains design/source-review evidence only, left `needs-review`; see `.ai/tasks/_archive/049-knowledge-package-shell-fixes.md` for the full re-derivation and its reasoning.
